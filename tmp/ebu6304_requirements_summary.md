# EBU6304 Group Project Handout Requirements Summary

Source: `docs/EBU6304_GroupProjectHandout.pdf`

## Project Goal

- Build a Teaching Assistant recruitment system for BUPT International School.
- Use Agile methods across requirements, analysis/design, implementation, testing, and iteration planning.
- Define scope clearly, keep the design simple/modular/extensible, and justify decisions and trade-offs.

## Allowed Technical Scope

- The software must be either:
- A stand-alone Java application, or
- A lightweight Java Servlet/JSP web application.
- Data storage must use simple text-based files only: `.txt`, `.csv`, `.json`, or `.xml`.
- Do not use a database.
- Do not introduce framework-heavy solutions that move the work away from core software engineering objectives.

## Functional Direction

- High-level suggested functions include:
- Applicant profile creation
- CV upload
- Job browsing
- Job application
- Application status tracking
- Job posting by MO
- Applicant selection by MO
- Workload checking by admin
- AI-powered functions are allowed, such as skill matching, missing-skill identification, and workload balancing.
- A complete prototype is required.
- Not every prototyped feature must be fully implemented in code.
- A selected set of core functions must be fully implemented.

## AI Use Rules

- AI can assist brainstorming, story writing, prototyping, design, coding, debugging, and testing.
- The team must not rely blindly on AI outputs.
- Team members must be able to explain why AI suggestions were made and how they were modified.
- Any AI-powered feature must combine structured logic with AI-based interpretation and provide explainable results.

## Team and GitHub Requirements

- Each group has 6 students.
- All students should work on all aspects of the project.
- The project should be managed using Agile practices such as Scrum, standups, and iterative delivery.
- Each member must have a visible branch and corresponding commits on GitHub.
- GitHub evidence is mandatory for individual contribution.
- All members should be collaborators on the main repository.
- The main repository / master branch must be accessible to the assigned teaching assistant.
- GitHub activity should include commits, pull requests, issues, and README updates where relevant.
- Insufficient GitHub evidence can reduce individual marks.
- By assessment dates, sub-branch work should be merged into the main branch.

## Practical Rules For Future Work

- Keep every deliverable aligned to a Java or Java Servlet/JSP implementation path.
- Avoid any database-related design or implementation.
- When proposing features, distinguish between:
- Prototype-only features
- Core features that must actually work
- For every backlog item, maintain acceptance criteria, priority, estimate, and sprint placement.
- Preserve evidence for fact-finding, feedback, sprint planning, testing, and GitHub contribution.
- Prepare for viva questions on:
- Requirement choices
- Trade-offs
- AI usage
- Testing decisions
- Individual contribution
