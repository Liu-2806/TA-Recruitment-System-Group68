# 简历输入模块中文说明手册

## 1. 模块目标

本模块用于处理 Teaching Assistant Recruitment System 中的候选人输入流程。当前 demo 的目标是验证以下链路在课程 handout 约束下可以跑通：

- 用户上传 PDF 格式简历
- 系统提取简历文本
- 系统将文本转换为结构化候选人数据
- 系统读取现有岗位数据
- 系统为每个岗位生成匹配分数与解释文本
- 系统将结果保存为文本型输出文件

该实现遵循 handout 的限制：

- 使用 Java 技术路线
- 不使用数据库
- 所有输入输出使用文本文件
- 模块结构可扩展，便于后续持续开发和团队协作

## 2. 当前 demo 的处理流程

### 2.1 输入

- 输入文件：`demo-data/sample_resume.pdf`
- 岗位文件：`demo-data/job_postings.csv`

### 2.2 处理步骤

1. `PdfResumeParser` 使用 PDFBox 提取 PDF 中的文本内容。
2. `ResumeStructurer` 基于规则从原始文本中提取：
- 姓名
- 邮箱
- 电话
- 教育背景
- 技能列表
- 经历摘要
3. `JobPostingRepository` 从文本型 CSV 文件中加载岗位数据。
4. `ResumeMatchingService` 将候选人与所有岗位逐一匹配。
5. 匹配器有两种模式：
- 默认模式：`LocalKeywordJobMatcher`
- API 模式：`OpenAiCompatibleJobMatcher`
6. `OutputWriter` 输出结构化结果和匹配结果。

### 2.3 输出

- 结构化候选人信息：
  `output/candidate-profile.json`
- 岗位匹配结果：
  `output/job-match-results.json`

## 3. 主要模块说明

### 3.1 入口模块

- `src/main/java/edu/qmul/ta/DemoApplication.java`

作用：

- 读取输入路径
- 装配服务对象
- 执行完整流程
- 输出运行结果

### 3.2 PDF 解析模块

- `src/main/java/edu/qmul/ta/parser/PdfResumeParser.java`

作用：

- 使用 PDFBox 将 PDF 简历转换为纯文本

### 3.3 结构化提取模块

- `src/main/java/edu/qmul/ta/parser/ResumeStructurer.java`

作用：

- 从简历文本中提取结构化字段
- 当前使用规则法，后续可以替换为更严格的规则、模板识别或 LLM 辅助抽取

### 3.4 岗位读取模块

- `src/main/java/edu/qmul/ta/io/JobPostingRepository.java`

作用：

- 从文本型 CSV 中读取岗位信息
- 保证不依赖数据库

### 3.5 匹配模块

- `src/main/java/edu/qmul/ta/match/LocalKeywordJobMatcher.java`
- `src/main/java/edu/qmul/ta/match/OpenAiCompatibleJobMatcher.java`

作用：

- 本地关键词匹配器用于 demo 验证主流程
- API 匹配器用于后续接入真实外部模型服务

### 3.6 输出模块

- `src/main/java/edu/qmul/ta/io/OutputWriter.java`

作用：

- 将结构化简历和匹配结果写成 JSON 文本文件

## 4. API 路径说明

当前代码已经预留 API 路径，但未绑定具体平台账号。要启用 API 模式，需要设置：

- `LLM_API_URL`
- `LLM_API_KEY`
- `LLM_MODEL`

若这三个环境变量都存在，系统会自动启用 `OpenAiCompatibleJobMatcher`。

推荐协作方式：

- 仓库中只保留 `.env.example`
- 每个成员在本地创建自己的 `.env.local`
- `.env.local` 不提交到 Git
- `scripts/run-demo.ps1` 启动时自动读取 `.env.local`
- `.env.local` 中的值即使带引号也可以被正确读取
- 若使用 DeepSeek，`LLM_API_URL` 可以填写 `https://api.deepseek.com` 或 `https://api.deepseek.com/v1`，代码会自动补全到聊天接口地址

当前 API 匹配器的输入内容包括：

- 候选人结构化信息
- 单个岗位信息

期望 API 返回内容至少包含：

- `score`
- `explanation`

说明：

- 当前这部分已经具备接线能力
- 但还没有与你们最终选定的供应商做正式联调
- 后续应继续完善 prompt、输出解析、异常重试和限流控制

## 5. 如何运行

在 PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run-demo.ps1
```

运行完成后会生成：

- `output/candidate-profile.json`
- `output/job-match-results.json`

若启用了 API 模式，终端会额外打印：

- `Matcher mode: api-llm`
- `LLM endpoint: ...`
- `LLM model: ...`

若没有启用 API 模式，终端会打印：

- `Matcher mode: local-keyword`

## 6. 当前版本的已验证能力

- 已验证 Java 环境下可以读取 PDF 简历
- 已验证可以从 PDF 中提取候选人基本结构化信息
- 已验证可以读取文本格式岗位数据
- 已验证可以输出每个岗位的匹配分数和解释文本
- 已验证整个链路符合“Java + 文本文件 + 无数据库”的 handout 约束

## 7. 当前版本的局限

- 结构化提取仍然是规则法，准确率取决于简历格式
- API 路径已写好，但尚未使用真实接口做联调
- 当前是控制台 demo，尚未接入正式上传界面
- 岗位数据目前为示例数据，后续需要替换为正式岗位数据源

## 8. 后续建议
