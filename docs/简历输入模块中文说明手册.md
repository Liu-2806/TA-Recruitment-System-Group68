# 简历输入与匹配模块中文说明手册

## 1. 模块范围

本手册对应当前主框架 `src/com/bupt/ta` 中由我负责的两个模块：

- 输入模块
- 匹配模块

本次实现严格遵循课程 handout 与当前组内框架约束：

- 使用 Java Servlet / JSP
- 数据仅使用文本文件
- 不使用数据库
- 以模块化方式接入现有 controller / service / repository / view 结构

本次只完成我负责的功能，不扩展到其他组员负责的业务模块。

## 3. 输入模块功能说明

### 3.1 功能目标

TA 从个人资料页上传 PDF 简历后，系统需要完成：

1. 保存原始 PDF 文件
2. 从 PDF 中提取文本
3. 将文本整理为结构化数据
4. 将结构化结果写回 TA 数据文件
5. 在 TA 页面展示提取结果

### 3.2 处理流程

1. TA 在 `/ta/profile` 页面上传 PDF。
2. `TAResumeUploadServlet` 接收 `multipart/form-data` 请求。
3. `ResumeServiceImpl` 校验文件类型和大小。
4. PDF 文件保存到 `data/resumes/`。
5. `PdfResumeExtractor` 使用 PDFBox 提取原始文本。
6. `ResumeStructurer` 以规则法提取结构化字段。
7. 结果写入 `data/users/ta.json` 对应 TA 记录中的 `extractedResume` 字段。
8. `profile.jsp` 展示当前简历文件名、上传时间和结构化结果。

### 3.3 当前提取字段

当前已提取的结构化字段包括：

- `name`
- `email`
- `phone`
- `education`
- `skills`
- `experienceHighlights`
- `rawText`

### 3.4 当前输入限制

- 仅接受 `.pdf`
- 文件大小上限为 `5MB`
- 若 TA 数据不存在，上传会报错

## 4. 匹配模块功能说明

### 4.1 功能目标

在 TA 查看岗位详情、MO 查看申请人详情时，系统根据 TA 的结构化简历与岗位要求生成：

- 匹配分数
- 一段解释文本
- 已匹配技能
- 缺失技能
- 匹配方法标记

### 4.2 处理流程

1. 系统从 `data/users/ta.json` 读取 TA 结构化简历。
2. 系统从 `data/postings/postings.json` 读取岗位信息。
3. `RecommendationServiceImpl` 判断 LLM 配置是否完整。
4. 若 `.env.local` 或环境变量中存在完整 API 配置，则调用 `OpenAiCompatibleMatcher`。
5. 若未配置 API，或 API 调用失败，则自动退回 `LocalRuleMatcher`。
6. 结果会在 TA 岗位详情页和 MO 申请详情页展示。

### 4.3 LLM 做了什么

当前版本中，AI 没有直接负责 PDF 提取。

AI 负责的内容是：

- 接收已经结构化好的候选人信息
- 接收单个岗位的岗位说明与技能要求
- 输出一个 `score`
- 输出一段 `explanation`

这意味着当前设计中：

- PDF 文本提取是传统程序逻辑
- 结构化提取是规则法
- AI 只负责岗位匹配分析与解释生成

这样更容易在 demo / viva 中解释 AI 的职责边界，也更符合模块化设计。

当前 LLM prompt 的设计还额外遵守以下解释性原则：

- 只分析系统传入的结构化简历字段与岗位字段，不直接读取原始 PDF，不引入外部知识
- 按“技能重合度、教育背景相关性、教学/助教/学术支持经历、岗位职责适配性、关键缺口”五个维度组织判断
- 若输入中不存在某项证据，prompt 要求模型明确说明“缺少证据”，而不是自行脑补
- 输出中的 `explanation` 必须同时覆盖匹配证据、主要缺口与适配性判断，并明确其性质是辅助建议，不是自动录用决策

### 4.4 匹配输出字段

当前匹配模块统一输出：

- `score`
- `explanation`
- `method`
- `matchedSkills`
- `missingSkills`

在申请记录中，还会同步写入：

- `skillMatchScore`
- `skillMatchExplanation`
- `matchMethod`

## 6. API 私有配置方案

为了避免协作开发中泄露密钥，当前模块不在源码中写入 API 信息。

推荐方式：

1. 仓库中仅保留 `.env.example`
2. 每个成员本地创建 `.env.local`
3. 在 `.env.local` 中填写：
   - `LLM_API_URL`
   - `LLM_API_KEY`
   - `LLM_MODEL`
4. `.env.local` 不提交到 Git

当前代码支持：

- 直接读取系统环境变量
- 自动读取仓库根目录 `.env.local`
- 兼容带引号的配置值
- 兼容 DeepSeek 的 base URL 自动补全
